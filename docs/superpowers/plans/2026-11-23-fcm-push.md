# FCM push bildirishnomalar — ish rejasi

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shef Django admin'da tanlagan foydalanuvchilariga (mehmon ham) iOS/Android push yuboradi, har biriga o'z tilida.

**Architecture:** `apps/notifications` ga `audience`+`recipients` va push holati, `PushDevice` jadvali va qurilma API'si qo'shiladi. Admin faqat `push_status=pending` qo'yadi; `push_worker` buyrug'i (alohida compose servisi) `firebase-admin` bilan yuboradi. Mobil `@react-native-firebase/messaging` bilan token oladi va ro'yxatdan o'tkazadi.

**Tech Stack:** Django 6 / DRF, firebase-admin, pytest; Expo 57 (CNG), @react-native-firebase/app + messaging.

**Spec:** `docs/superpowers/specs/2026-11-23-fcm-push-design.md`

## Global Constraints
- Til: `user.language` (`uz`/`kr`/`ru`) → `common.lang.CLIENT_TO_DB` → `pick(obj, "title"/"body", lang)` (bo'sh bo'lsa uz).
- FCM multicast bo'lagi: 500 token.
- Yaroqsiz token xatolari (`UnregisteredError`, `SenderIdMismatchError`, `InvalidArgumentError`) → `PushDevice.is_active=False`.
- `data`: `{"notification_id": str(id), "kind": kind, "screen": "notifications"}`; Android channel `default`, rang `#ED020A`; iOS sound `default`.
- Env: `FIREBASE_CREDENTIALS_FILE` (bo'sh → push o'tkazib yuboriladi, `push_status=failed`).
- Mobil: versiya `1.3.0`, versionCode `10`, branch `feat/push` (`feat/telegram-auth` dan).

## Review Focus
- Ikki worker bir vaqtda ishlasa — bitta xabar bir marta yuboriladi (`select_for_update(skip_locked=True)` + `sending` holati). Test: Task 3 `test_claim_marks_sending_once`.
- Bitta token boshqa hisobga o'tsa (logout → mehmon, boshqa odam kirdi) — eski egasiga ketmaydi. Test: Task 2 `test_register_moves_token_to_new_owner`.
- Tanlanganlarning hech birida qurilma yo'q — xabar `done`, `push_sent=0`, xato emas. Test: Task 3 `test_no_devices_done_zero`.
- Firebase sozlanmagan server — admin yiqilmaydi, xabar ilova ichida ko'rinadi. Test: Task 3 `test_unconfigured_marks_failed`.
- Eski `user` FK qatorlari migratsiyadan keyin o'sha userga ko'rinishda qoladi. Test: Task 1 `test_migration_moves_user_to_recipients`.
